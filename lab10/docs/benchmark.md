# Результаты сравнения производительности

**Условия измерений:**
- Локальный сервер: `localhost:8000`
- База данных: PostgreSQL (7 записей)
- Инструмент: Вкладка Network в браузере Google Chrome

| Сценарий | Код ответа | Заголовок X-Cache | Время выполнения |
|----------|------------|-------------------|------------------|
| Первый запрос (промах, база) | 200 OK | MISS |  12 мс |
| Второй запрос (попадание, кеш) | 200 OK | HIT |  1 мс |
| Третий запрос (попадание, кеш) | 200 OK | HIT |  1 мс |

**Анализ:**
Кеширование списка бронирований дало ускорение примерно **в 12 раз** (с 12 мс до 1 мс). Чем больше данных в базе, тем заметнее будет выигрыш. Для тяжелых запросов (например, поиск по названию `ILIKE` или отчеты с `GROUP BY`) выигрыш был бы еще больше (в 50–100 раз), так как кеш полностью исключает работу СУБД.
