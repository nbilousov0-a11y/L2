Вариант 1. Система бронирования туристических услуг

1. Описание предметной области
Система бронирования туристических услуг предназначена для организации работы туристического агентства. Система учитывает клиентов, туристические предложения, даты поездок и бронирования. Клиент выбирает подходящее предложение и оформляет бронирование, менеджер управляет предложениями и обрабатывает заявки, администратор контролирует пользователей и работу системы.

Решаемая проблема: бронирование осуществляется по телефону или через разные несвязанные сервисы, из-за чего сложно отслеживать актуальные предложения, занятость дат и статусы заявок.

Цель системы: централизованный учёт туристических предложений, оформление и контроль бронирований.

2. Пользователи и роли
Роль	Назначение	Основные функции	Уровень доступа
Администратор	Управление системой и пользователями	Управление пользователями и ролями, управление справочниками, просмотр всех бронирований, формирование отчётов	Полный доступ
Менеджер	Управление предложениями и обработка заявок	Создание, редактирование, удаление предложений, обработка заявок, изменение статусов, формирование отчётов	Расширенный доступ
Клиент	Выбор и бронирование туристических услуг	Просмотр и поиск предложений, оформление бронирования, просмотр своих заявок, отмена бронирования, отзывы	Ограниченный доступ

3. Сценарии использования
UC-01. Просмотр и поиск туристических предложений
Инициатор: Клиент
Шаги:
1.	Клиент входит в систему.
2.	Переходит в раздел «Туристические предложения».
3.	Задаёт параметры поиска (страна, город, цена, даты).
4.	Система отображает список подходящих предложений.
5.	Клиент открывает карточку предложения для подробного просмотра.
Ожидаемый результат: клиент видит список подходящих предложений с подробной информацией.

UC-02. Оформление бронирования
Инициатор: Клиент
Шаги:
1.	Клиент выбирает туристическое предложение.
2.	Нажимает «Забронировать».
3.	Указывает даты поездки и количество человек.
4.	Система проверяет доступность мест на выбранные даты.
5.	Клиент подтверждает бронирование.
6.	Система создаёт бронирование со статусом «новое».
7.	Система отправляет уведомление клиенту и менеджеру.
Ожидаемый результат: бронирование создано, клиент и менеджер получили уведомления.

UC-03. Обработка заявки менеджером
Инициатор: Менеджер
Шаги:
1.	Менеджер входит в систему.
2.	Переходит в раздел «Заявки».
3.	Открывает новую заявку.
4.	Проверяет данные клиента и выбранного предложения.
5.	Подтверждает или отклоняет бронирование.
6.	Система изменяет статус бронирования.
7.	Система отправляет уведомление клиенту.
Ожидаемый результат: заявка обработана, статус изменён, клиент уведомлён.

UC-04. Управление туристическими предложениями
Инициатор: Менеджер
Шаги:
1.	Менеджер входит в систему.
2.	Переходит в раздел «Предложения».
3.	Создаёт новое предложение или редактирует существующее.
4.	Указывает название, страну, город, цену, даты, количество мест.
5.	Сохраняет изменения.
6.	Система обновляет каталог предложений.
Ожидаемый результат: каталог предложений обновлён.

UC-05. Отмена бронирования клиентом
Инициатор: Клиент
Шаги:
1.	Клиент входит в систему.
2.	Переходит в раздел «Мои бронирования».
3.	Выбирает активное бронирование.
4.	Нажимает «Отменить».
5.	Система проверяет возможность отмены.
6.	Система изменяет статус на «отменено».
7.	Система отправляет уведомление менеджеру.
Ожидаемый результат: бронирование отменено, статус обновлён.

UC-06. Управление пользователями и ролями
Инициатор: Администратор
Шаги:
1.	Администратор входит в систему.
2.	Переходит в раздел «Пользователи».
3.	Добавляет нового пользователя или изменяет данные существующего.
4.	Назначает роль (администратор, менеджер, клиент).
5.	Сохраняет изменения.
6.	Система обновляет список пользователей и их права доступа.
Ожидаемый результат: пользователь добавлен или изменён, роль назначена.

UC-07. Формирование отчётов
Инициатор: Менеджер / Администратор
Шаги:
1.	Пользователь входит в систему.
2.	Переходит в раздел «Отчёты».
3.	Выбирает тип отчёта (по бронированиям, по загрузке предложений).
4.	Задаёт период.
5.	Система формирует отчёт.
6.	Пользователь просматривает или выгружает отчёт.
Ожидаемый результат: отчёт сформирован и доступен для просмотра/выгрузки.

7. Концепция информационной системы
Назначение и цель: система предназначена для централизованного учёта туристических предложений, оформления и контроля бронирований. Цель — упростить клиентам выбор и бронирование услуг, а менеджерам — управление предложениями и заявками.

Основные возможности:
•	ведение каталога туристических предложений;
•	поиск и фильтрация предложений;
•	оформление, обработка и отмена бронирований;
•	отслеживание статусов заявок;
•	управление пользователями и ролями;
•	формирование отчётов;
•	уведомление клиентов и менеджеров.

Тип системы: веб-приложение (клиент-серверная архитектура, трёхуровневая).

Основные компоненты и их взаимодействие:
•	Frontend — взаимодействует с пользователем, отправляет запросы к Backend по HTTP/REST.
•	Backend — обрабатывает запросы, реализует бизнес-логику, обращается к БД, сервисам аутентификации, уведомлений и платёжному сервису.
•	База данных — хранит данные о пользователях, предложениях, бронированиях, оплатах.
•	Сервис аутентификации — проверяет учётные данные, выдаёт токены доступа.
•	Сервис уведомлений — отправляет email/SMS через внешний шлюз.
•	Внешние сервисы — платёжный сервис, email/SMS-шлюз.

Результат использования: клиент быстро находит и бронирует туристическую услугу, менеджер эффективно управляет предложениями и заявками, администратор контролирует работу системы.
